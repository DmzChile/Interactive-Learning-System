# C / LAB — Interactive C Learning

개인용 C17 학습 웹 앱의 첫 구현입니다. 목표를 정하고 코드를 작성한 뒤, 자신의 설명과 코드를 비교하는 AI 피드백을 받습니다.

**현재 상태:** 로컬 앱과 API 어댑터 구현, 자동 검증 18개 통과. 실제 OpenAI API 호출과 브라우저에서의 수동 조작·화면 검증은 아직 수행하지 않았습니다. 실모델의 평가 품질은 미검증입니다.

## 1. 실행하기

Node.js 22 이상이 필요합니다. 외부 패키지를 설치하지 않아도 실행됩니다.

압축을 풀고 `interactive-c-learning` 폴더를 터미널에서 여세요. Windows에서는 해당 폴더에서 PowerShell이나 VS Code 터미널을 열면 됩니다.

### API 키 없이 모의 학습

```powershell
node server.mjs --offline
```

터미널에 표시되는 `http://127.0.0.1:3210/#token=...` **주소 전체**를 브라우저에서 여세요. 이 토큰은 로컬 서버 접속용이며 OpenAI API 키가 아닙니다.

1. 학습 목적·경험·설명 선호를 입력해 프로필을 만듭니다.
2. **모의 학습 시작**을 선택합니다.
3. 목표를 작성하거나 예시 목표를 고르고 **과제 제안 받기**를 누릅니다.
4. 조건을 확인하고 **이 과제로 시작하기**를 누릅니다.
5. 코드를 작성해 제출하고, 질문 1~2개에 답변을 기록합니다.
6. 평가를 확인하고 수정하거나 세션을 종료합니다.
7. **JSON 저장**으로 학습 파일을 내려받습니다. 다음 실행에서 **불러오기**로 이어갑니다.

모의 모드는 고정된 과제·질문·보류 판정으로 앱 흐름을 확인하는 기능입니다. 코드의 옳고 그름을 판정하거나 실제 숙련도를 갱신하지 않습니다. 일반 목표는 입력과 경계를 학습자가 구체화하는 모의 과제로 제공됩니다.

`examples/demo-session.json`은 코드 제출 후 질문에 답하는 단계의 모의 학습 예시입니다. 불러오기로 바로 확인할 수 있습니다.

### 실제 AI 학습

```powershell
node server.mjs
```

터미널의 숨김 입력 프롬프트에 자신의 OpenAI API 키를 입력하세요. 아무것도 입력하지 않고 Enter를 누르면 오프라인으로 시작합니다. 키를 이 대화, 소스 파일, 명령행 인자 또는 JSON 파일에 넣을 필요가 없습니다.

웹 화면에서 **AI 학습 시작**을 누르고 전송 안내에 동의하면 API를 호출합니다. 코드·답변·목표·학습 경험·추정 수준이 전송되며, 선택 입력한 학력은 전송하지 않습니다. API 사용에는 별도 요금이 발생할 수 있습니다.

기본 모델은 `gpt-5-mini`입니다. 계정에서 사용 가능한 구조화 출력 지원 모델로 바꾸려면 다음처럼 실행하세요.

```powershell
node server.mjs --model gpt-5-mini --port 3210
```

키를 입력했다는 사실과 인증이 성공했다는 사실을 구분합니다. 첫 실제 요청이 성공하기 전에는 **키 설정됨 · 연결 미확인**으로 표시합니다. API 연결이 실패해도 기존 데이터의 열람·편집·저장이 가능합니다. 모의 세션을 실제 평가로 바꾸지 않으며, 실제 AI 학습은 새 세션에서 시작합니다.

### 종료와 저장

- 터미널에서 Ctrl+C로 종료합니다. 브라우저 메모리의 학습 상태는 JSON으로 저장해야 다음에 복원할 수 있습니다.
- 브라우저 영구 저장소에 자동 저장하지 않습니다. 저장하지 않은 변경이 있으면 페이지를 떠날 때 경고합니다.
- 요청 중에 저장한 파일은 복원 시 해당 요청을 `interrupted`로 처리합니다. 자동 재요청이나 중복 수준 갱신을 하지 않습니다.
- 서버를 다시 실행하면 접속 토큰이 바뀝니다. 새로 출력된 주소 전체를 사용하세요. 서버 실행 중에는 같은 주소로 새로고침할 수 있습니다.
- API 키는 서버 프로세스 메모리에만 보관합니다. 종료 후 다시 입력합니다.

## 2. 구현한 기능

| 영역 | 현재 동작 |
| --- | --- |
| 프로필 | 사용자 사실과 추정 수준 분리, 선택 학력, 학습 시간·경험·설명 선호 |
| 과제 | 사용자 목표 기반 제안, 입력·요구 동작·제한·완료 기준, 명시적 확정 |
| 목표 변경 | 이전 목표와 과제·제출본 보존, 새 기준 재확정 |
| 편집 | C 텍스트 편집, 줄 번호, Tab 들여쓰기, Ctrl+Enter 제출 |
| 제출 | 시각과 ID가 있는 변경 불가능한 코드 사본, 버전 열람 |
| 질문 | 실제 코드 줄과 연결한 질문 1~2개, 답변·작성 중 답변 저장 |
| 도움 | 힌트·전체 해설의 요청 이력과 제출 버전 연결 |

| 수정 | 수정본에 새 버전 부여, 이전 답변과 평가 혼합 방지 |
| 종료 | 완료 기준 충족 추정/조기 종료 구분, 보수적인 수준 갱신 |

코드는 컴파일하거나 실행하지 않습니다. 화면의 평가는 코드와 답변을 읽고 추론한 결과입니다. 테스트 통과 표시, 채점 서버, 샌드박스, 다른 언어, 공개 배포, 계정·동기화 기능은 포함하지 않습니다.

## 4. 검증 명령

```powershell
npm test
npm run check
```

테스트는 앱의 상태 처리와 API 어댑터를 검증합니다. 외부 API 비용이 발생하지 않으며 학습자 C 코드를 실행하지 않습니다. API 응답은 테스트용 대체 응답을 사용합니다.

실제 모델 검증은 `docs/evaluation-cases.json`의 7개 사례를 이용해 별도로 수행해야 합니다. 근거를 구조적으로 검증한다는 사실이 판정 내용의 정확성을 보장하지는 않습니다.

## 5. 로컬 서버 경계와 제한

- 서버는 `127.0.0.1`에만 바인딩합니다. 공유 서비스·역방향 프록시 배포용 구성이 아닙니다.
- Host와 Origin, Fetch Metadata, 무작위 로컬 접속 토큰을 확인합니다. CORS만으로 인증하지 않습니다.
- 정적 자산은 허용된 파일 목록만 제공합니다. 서버 소스나 임의 경로를 읽는 API는 없습니다.
- API 키는 프런트엔드·학습 JSON·프롬프트·로그에 넣지 않습니다. API 인증 헤더에만 사용합니다.
- AI에게 파일·셸·코드 실행 도구를 제공하지 않습니다. 출력과 사용자 입력은 텍스트 노드로 렌더링합니다.
- 가져온 JSON은 정책·API 주소·서버 모델·고정 지침을 덮어쓰지 않습니다. 모델명 저장 필드는 학습 파일의 참고 정보입니다. 실제 요청 모델은 서버 시작 옵션으로 정합니다.
- C 코드 24,000자/600줄, JSON 2 MB, API 요청 150 KB, 학습 맥락 100 KB, 생성 한도 평가 20,000토큰·기타 요청 10,000토큰(내부 추론 포함), API 시간제한 180초(화면 대기 195초), 자동 재시도 0회입니다.
- 기본 `gpt-5-mini`는 `reasoning.effort: low`로 요청합니다. 다른 모델에는 이 옵션을 강제하지 않습니다.
- 서버 내 동시 AI 요청은 1개, 분당 요청은 20개까지입니다. 최근 요청 200개의 결과를 메모리에 보관해 동일 요청의 중복 호출을 막습니다. 서버 재시작을 넘는 API 과금 중복 방지는 보장하지 않습니다.
- 세션 최대 30개, 세션별 코드 버전 40개·질문 100개·평가 50개를 지원합니다. 한도를 넘으면 기존 기록을 임의로 삭제하지 않고 작업을 거부합니다.

## 6. 참고한 공식 API 문서

- [Structured model outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- [Migrate to the Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses)
- [GPT-5 Mini model](https://developers.openai.com/api/docs/models/gpt-5-mini)

이 구현은 Responses API의 `text.format` JSON Schema와 `store: false`를 사용합니다. 서버에 대화 ID만 남기는 방식에 의존하지 않고 학습 파일에서 다음 요청의 맥락을 다시 구성합니다. `store: false`를 API 제공자의 모든 데이터 처리·보관이 없다는 의미로 해석해서는 안 됩니다.

### 답변 전송 문제 확인

`답변 기록`은 답변을 학습 상태에 기록합니다. 모든 질문에 답한 뒤 `코드와 설명 평가받기`를 눌러야 코드와 답변이 함께 전송됩니다.

실패하면 화면에 오류 메시지, 확인 단계, 오류 코드, HTTP 상태와 요청 ID가 남습니다. 서버 터미널의 `[tutor]` 기록에서 같은 요청 ID를 확인할 수 있습니다.

- `validated`: 로컬 서버가 요청을 검증함. `answerCount`는 기록된 답변 수입니다.
- `upstream_request`: 서버에서 OpenAI 호출을 시작함. API가 요청을 수신했다는 확인은 아닙니다.
- `upstream_headers`: OpenAI의 HTTP 응답 헤더 수신. `status`가 400이면 요청 거절, 401이면 인증 실패 등입니다.
- `upstream_body`: 응답 본문까지 수신함. 이후 `INVALID_RESPONSE`는 전송 실패가 아니라 응답 형식 또는 근거 검증 실패입니다.
- `completed`: 결과 검증 완료. `failed`에는 마지막 도달 단계와 오류 코드가 남습니다.

이 진단 로그에는 코드, 답변 본문, API 키, 인증 헤더 또는 API의 원본 오류 본문을 기록하지 않습니다. 학습 상태 JSON의 저장 형식은 변경하지 않습니다.

### AI 응답 미완료 처리

평가 응답은 7개 항목과 근거를 포함하므로 생성 한도를 20,000토큰으로 두고 설명과 인용을 간결하게 요청합니다. 다른 작업은 10,000토큰입니다. 이 한도에는 내부 추론도 포함되며, 한도 확대는 평가 요청의 최대 사용량을 늘릴 수 있습니다. 자동 재시도는 하지 않습니다.

`INCOMPLETE_TOKENS`는 API가 `incomplete_details.reason=max_output_tokens`를 반환한 경우에만 표시합니다. 생성·추론 토큰 수가 제공되면 화면과 진단 로그에 함께 표시합니다. `CONTENT_FILTER`와 `RESPONSE_FAILED`는 별도로 처리합니다. 사유가 없는 미완료 응답은 토큰 부족으로 단정하지 않습니다. 미완료 JSON은 파싱 가능하더라도 평가에 반영하지 않습니다.
