## 학습 상태와 불변 조건

| 상태 | 다음 단계 | 프로그램이 확인하는 조건 |
| --- | --- | --- |
| goal | confirm | 목표가 있고 제안 응답이 유효함 |
| confirm | coding | 사용자가 과제를 확정함. 제안 후 목표 초안을 바꿨으면 재제안 필요 |
| coding | questions | 확정된 과제가 있고 새 코드 사본이 생성됨 |
| questions | evaluation | 최소 1개 질문에 답하고 미답변 질문이 없음. 평가 응답의 근거가 유효함 |
| questions / evaluation | coding | 사용자가 수정을 선택함 |
| 열린 상태 | closed | 사용자가 종료함. 요청 중에는 종료하지 않음 |
| 열린 상태 | goal | 목표 변경을 확정함. 이전 기록을 보존하고 기준을 재설정함 |

- 작성 중 코드와 제출 코드는 서로 다른 필드이다. 질문·평가는 제출 ID로 연결한다.
- 제출된 답변은 기존 평가의 근거로 남긴다. 수정·정정은 새 기록으로 추가한다.
- 답변 초안과 목표 초안도 JSON에 저장한다.
- 질문·평가는 존재하는 버전과 과제에 연결되어야 한다.
- 근거의 인용문은 해당 코드 줄·답변·과제의 정확한 부분 문자열이어야 한다.
- AI가 제시한 상태 변경 필드를 직접 반영하지 않는다. 허용된 응답 종류를 검증한 다음 프로그램이 상태를 바꾼다.
- 요청 결과는 같은 요청 ID에 한 번만 적용한다. 복원 시 pending은 interrupted로 바꾼다.
- 거절·불완전 응답·스키마 실패는 기존 수준이나 학습 단계를 갱신하지 않는다.

## 수준 갱신 규칙

수준은 미평가 → 입문 → 연습 중 → 독립 적용 → 응용 순서로 관리한다.

1. 실제 AI 세션을 종료할 때만 검토한다. 모의 결과는 변경하지 않는다.
2. 변경 제안에는 과제에 포함된 개념, 실제 코드와 답변 근거가 모두 있어야 한다.
3. 한 세션 종료에서 한 단계보다 크게 바꾸지 않는다.
4. 독립 적용은 해당 개념의 근거가 있는 실제 세션 2개 이상, 응용은 3개 이상이 필요하다.
5. 독립 적용·응용 제안은 현재 과제의 도움 이력이 없고 7개 항목이 모두 충족일 때만 검토한다.
6. 수준 하향도 2개 이상 세션에서 근거가 있어야 한다. 단일 관찰로 낮추지 않는다.
7. 해당 평가에 미해결 정정 요청이 있으면 수준을 유지한다. 재평가 결과는 별도 평가로 기록된다.
8. 제안 수준·변경 전후 값·실제 반영 여부의 이유를 기록한다. 사용자 사실은 바꾸지 않는다.

이 규칙은 첫 버전의 보수적인 정책이다. 세션 수가 곧 숙련을 입증하지는 않으며, 실제 사례 관찰을 거쳐 기준을 조정해야 한다.

## 자동 검증 결과

`npm test`: 18개 통과, 실패 0개. `npm run check`: JavaScript 문법과 HTML의 로컬 자산 참조 통과.

- 모의 세션의 생성부터 종료·복원까지
- 제출 코드의 불변성과 수정 버전의 질문·평가 분리
- 미답변 질문·답변 초안·진행 중 요청 복원
- 잘못된 JSON, 초과 크기, 알 수 없는 버전·필드, 잘못된 참조 거부
- 없는 줄·인용문·답변 근거 및 중복 평가 항목 거부
- 이해도 평가 전 답변 요구, 요청 중복 반영 방지
- 조기 종료와 근거 없는 수준 변경 방지, 정정 이력 반영
- 다음 세션으로 수준 이월, API 전송에서 선택 학력 제외
- 무인증·다른 Origin·다른 Host 거부, 서버 소스·임의 경로 미제공
- API 요청의 고정 지침·키 분리·구조화 출력 확인
- 인증·제한·네트워크·시간초과·응답 중단·거절 오류 처리

테스트 코드의 HTTP 요청은 로컬 시험 서버에만 보냈다. API 응답은 대체 함수로 공급했으며 OpenAI API를 호출하지 않았다. 학습자 C 코드는 테스트 과정에서도 실행하지 않았다.

## 남은 실제 검증

1. 사용자 환경의 Node.js 22 이상에서 서버 실행 및 브라우저 전체 흐름 확인.
2. 데스크톱/모바일/200% 확대에서 편집기·질문·JSON 저장과 복원 확인.
3. 실제 API 키로 과제·질문·힌트·평가·정정 호출 확인.
4. `evaluation-cases.json`의 각 사례를 2회 이상 평가하고 판정 및 근거 일관성 기록.
5. 학습자의 설명과 수정 경험을 관찰해 교육적 유용성 확인.

지원되는 브라우저 환경을 사용할 수 없어 실제 화면·키보드 흐름·WebMCP 등록은 검증하지 않았다. WebMCP는 기능 탐지 후 현재 상태 읽기와 코드 초안 편집만 등록하며, 지원하지 않는 브라우저에서는 기본 화면 기능을 사용한다.

평가 품질 검증의 첫 합격 기준은 아래와 같다. 이번 구현에서는 실모델로 측정하지 않았다.

- 허구의 줄·답변·인용문, 실행했다는 주장, 사용자 사실 임의 변경은 0건이어야 한다.
- 정상 코드와 잘못된 설명을 구분하고, 코드가 잘못됐지만 설명의 원리는 맞는 사례도 분리해야 한다.
- 배열 범위 초과와 수명이 끝난 객체 접근을 주요 문제로 지적해야 한다.
- 정보 부족 사례는 추가 질문이나 판단 보류를 사용해야 한다.
- 주석의 지침 변경 시도가 교육 지침·출력 형식을 바꾸지 않아야 한다.
- 동일 사례의 2회 평가에서 목표 충족/UB 관련 판정이 뒤집히면 원인을 검토하기 전 품질 검증을 통과 처리하지 않는다.

## 정지조건 처리

첨부 계획의 정지조건을 유지한다. 이번 구현 중 실제 보안 취약점, 해결 불가능한 요구사항 모순, 핵심 의미를 해석할 수 없는 지시는 확인되지 않았다.

Host 차단 테스트에서 Node의 fetch가 지정한 Host를 정규화하는 시험 도구 특성을 확인했고, 원시 HTTP 요청으로 실제 차단 응답(403)을 확인하여 시험 코드를 수정했다. 보호 로직을 완화하지 않았다.

향후 실제 취약점이 확인되면 위치·증거·영향·권장 수정 방향을 기록하고 사용자 확인 전에 해당 경로를 계속 구현하거나 배포하지 않는다.

## 대화 평가 시간초과 수정

- 서버 60초·화면 70초 제한을 서버 180초·화면 195초로 조정하고 공유 상수로 관리한다.
- 기본 gpt-5-mini 및 날짜 스냅샷에 reasoning.effort=low를 지정한다. 다른 모델에는 강제하지 않는다.
- 60초를 넘는 응답, 응답 본문 수신 중 시간초과, 실패 후 재요청을 대체 API와 가상 시간으로 검증한다. 실제 API 지연 및 평가 품질은 별도 실호출 확인이 필요하다.

## 답변 전송 진단

로컬 HTTP 서버를 통한 평가 요청에서 기록된 한국어 질문·답변이 OpenAI 요청의 learningData.questions에 동일하게 포함되는지, 반환된 평가가 상태에 반영되는지 통합 테스트했다. 외부 API는 대체 함수이며 실제 사용자 환경의 전송 장애가 재현되었다는 의미는 아니다. 오류를 화면에 유지하고 서버에 내용 없는 단계별 진단을 추가했다. API 거절과 응답 수신 후 근거 검증 실패를 구분한다.

## 미완료 응답 처리 수정

사용자 오류 보고는 upstream_body 단계의 INCOMPLETE로, 외부 응답 본문 수신 후 완료 상태 검사에서 실패했다는 것을 확인했다. 기존 오류에는 실제 status 및 incomplete_details.reason이 없으므로 해당 요청의 토큰 소진 여부까지 확정할 수는 없다.

평가 생성 한도 확대와 간결한 평가 지침을 추가하고, 토큰 소진·콘텐츠 필터·생성 실패·사유 불명 미완료를 구분한다. 허용된 상태/사유 및 정수 토큰 사용량만 진단에 기록한다. 26개 테스트와 구문 검사가 통과했다. 실제 API 호출의 성공 여부는 아직 검증하지 않았다.

## 생성 한도 확대

사용자 요청에 따라 평가 128,000토큰, 기타 요청 32,000토큰으로 확대했다. 수신 본문 한도 2 MB와 결과 JSON 한도 1 MB를 함께 적용한다. 기존 학습 파일 형식과 필드별 검증은 유지한다.
